# СПЕКА: 3D Tower Defense (конвейер пройден)

**Дата фиксации:** 14.09.2026
**Статус:** визуальные улучшения — итерация 2, проход ролей №2 (конвейер 14.09.2026), все замечания устранены.

## 1. Цель и ожидаемый результат

Полноценная 3D-игра Tower Defense в **одном HTML-файле**, запускаемая простым открытием `D:\game\index.html` в браузере (без сервера, без сборки). Ожидаемый результат: игра играбельна от стартового экрана до game over / любой волны, без ошибок в консоли, на русском языке, арт-стиль low poly.

## 2. Функциональные требования

### 2.1 Техническая платформа
- Three.js **r184** (последняя стабильная) через CDN jsdelivr: `three.module.js` + `addons/` (import map).
- `OrbitControls` из `three/addons/`.
- Весь остальной код, CSS, HTML — инлайн в одном файле.
- Модели процедурные low-poly из примитивов (`BoxGeometry`, `ConeGeometry`, `CylinderGeometry`, `IcosahedronGeometry`, `SphereGeometry` с малым числом сегментов, `flatShading: true`).
- Без внешних файлов моделей и текстур. Номера/HP-бары/тексты — canvas-текстуры (sprites), не DOM в 3D.
- Состояние игры — один объект `game` (деньги, жизни, волна, башни, монстры, фазы).
- Цикл через `requestAnimationFrame`; `dt` умножается на `game.speed` (0=пауза, 1=обычно, 2=ускоренно). Ускорение влияет на всё: движение, стрельбу, таймеры, анимации, частицы.
- Таргет 60 FPS при 60+ монстрах: переиспользование геометрий/материалов, пулы частиц и снарядов, удаление объектов из сцены и `dispose()`.

### 2.2 Сцена и карта
- Камера: вид сверху под углом ~50°, вращение и зум мышью (OrbitControls), `minPolarAngle`/`maxPolarAngle` запрещают уход под землю, зум ограничен (не влезать в землю, не улетать).
- Сетка **16×12** клеток на плоскости XZ, клетка = 1 юнит. Поле — трава (большой box/plane), клетки не рисуются отдельно.
- **Дорога** S-образная, 3 поворота, от входа (слева) до базы (справа). Визуально песок/грунт (плоский box высотой 0.08 над травой, цвет 0xd9b380).
- **Точки пути (центр дороги), world-координаты** (клетка = 1; центр клетки (i,j) = (i+0.5, j+0.5)):
  `(-0.5, 0, 2.5) → (4.5, 0, 2.5) → (4.5, 0, 8.5) → (10.5, 0, 8.5) → (10.5, 0, 4.5) → (16.5, 0, 4.5)`
- Множество клеток дороги (проходит ровно по центру этих клеток):
  - строка j=2: i=0..4
  - колонка i=4: j=3..8
  - строка j=8: i=5..10
  - колонка i=10: j=7,6,5,4
  - строка j=4: i=11..15
- **Вход** — портал/пещера на левом краю у начала дороги (x=-0.5). **База** — врата/кристалл на правом краю (x=16.5, z=4.5), куда ведёт дорога.
- Направление движения — по списку точек пути (длина пути для расчёта «ближе к базе» = пройденное расстояние от входа).
- **Декорации** на всех клетках, кроме дороги/слотов: low-poly сосны, кусты, камни, холмы. Генерация детерминированная (seed-генератор), к каждому объекту переменная высота/угол поворота/цвет. Строить на них нельзя (игра на них это и не позволяет — стройка только по слотам).

### 2.3 Слоты башен (22 штуки)
Плоские плитки (box 0.9×0.06×0.9) со светлой окантовкой (edge «рамка» — тонкий box или линия). Координаты клеток слотов:

`(0,1) (2,1) (4,1) (1,3) (3,3) (3,4) (3,6) (3,8) (5,3) (5,5) (5,7) (6,9) (8,9) (10,9) (9,5) (9,7) (7,7) (11,3) (13,3) (15,3) (11,5) (13,5)`

Проверено: ни один слот не пересекается с дорогой и между собой.

- При наведении на слот — подсветка плитки: зелёная рамка — свободен (кликабельно → панель постройки), красная — занят (клик → панель управления башней).
- Клик по траве/дороге/декорации мимо слотов → закрыть открытую панель и снять кольцо дальности.

### 2.4 Освещение и небо
- Ключевой `DirectionalLight` (интенсивность ~2.5, `castShadow=true`, shadow.camera подогнан под сцену ~[-20..20], mapSize 2048) + `HemisphereLight` (небо/земля) для мягкого рассеянного света.
- `renderer.shadowMap.enabled = true`, `PCFSoftShadowMap`.
- Отрисовка: `antialias: true`, `pixelRatio = min(devicePixelRatio, 2)`.
- Небо — светлый градиент: `scene.background` нельзя градиентом сразу — задаём `scene.background` цветной (0xbfe3ff) или, если эстетично, полноэкранный CSS-градиент за прозрачным canvas (alpha), но обязателен 3D-градиент-купол не требуется. **Решение:** полупрозрачный canvas не используем (Three.js рисует фон) — делаем светлое небо цветом scene.background + туман (fog) светлый для глубины.

### 2.5 Экономика
- Стартовые деньги: **400** монет.
- Деньги начисляются **только за убийство** монстра (не за прохождение волны).
- Награда = `floor(база × (1 + 0.03 × N))`, где N — номер волны.
- При убийстве над монстром взлетает и растворяется текст с суммой награды (canvas-спрайт или DOM-флоат, анимируется вверх + фейд).

### 2.6 Башни (5 типов × 3 уровня)

Базовая статистика (уровень 1):

| Тип | Цена | Урон | Скорострельность | Дальность | Особенность |
|-----|------|------|------------------|-----------|-------------|
| Лёд | 100 | 12 | 1.2/с | 3.0 | замедление 40% на 2с |
| Огонь | 150 | 20 | 0.8/с | 2.8 | AoE 1.2 + горение 3 урона/с на 3с |
| Молния | 200 | 18 | 1.0/с | 3.2 | цепь до 3 врагов, −30% за хоп |
| Яд | 175 | 8 | 1.5/с | 2.8 | яд 5/с на 4с, стак до 3 |
| Пушка | 300 | 90 | 0.4/с | 3.5 | взрыв радиусом 0.8 |

**Формулы уровней:**
- Урон: `round(база × 1.45^(lv-1))`
- Дальность: `база × 1.15^(lv-1)` (округление до 0.01)
- Скорострельность: `база × 1.12^(lv-1)` (округление до 0.01)
- Цена улучшения на уровень: `round(0.8 × базовая цена)` (одинакова на L1→L2 и L2→L3)
- Продажа: `floor(0.5 × суммарные вложения)` (постройка + все улучшения). Слот освобождается.

Готовые значения (база уже в таблице выше):
- Улучшение: Лёд 80, Огонь 120, Молния 160, Яд 140, Пушка 240.
- Лёд L2: урон 17, дальн 3.45, р.1.34 | L3: урон 25, дальн 3.97, р.1.51
- Огонь L2: урон 29, дальн 3.22, р.0.90 | L3: урон 42, дальн 3.70, р.1.00
- Молния L2: урон 26, дальн 3.68, р.1.12 | L3: урон 38, дальн 4.23, р.1.25
- Яд L2: урон 12, дальн 3.22, р.1.68 | L3: урон 17, дальн 3.70, р.1.88
- Пушка L2: урон 131, дальн 4.03, р.0.45 | L3: урон 189, дальн 4.63, р.0.50

Округление показателей: `round(x×100 + 1e-6)/100` (устойчиво к float-дрейфу на границе 0.5), урон — `round()`.

**Поведение:**
- Приоритет цели: враг в радиусе с наибольшим прогрессом по пути (ближайший к базе). Разрыв связей (очередь замен) не требуется — монстры не умирают со сменой пути.
- Башня плавно поворачивается к цели (turret/pivot group).
- Снаряды — реальные 3D-объекты, летят к цели (гомминг), при попадании — взрыв частиц цвета башни. Молния — светящаяся линия ~0.1с.
- **Эффекты выстрелов уникальны для каждого оружия (см. 2.6-1).**
- При наведении на слот или выборе башни — кольцо дальности на земле (RingGeometry, прозрачный MeshBasicMaterial).
- Визуал уровня: башня растёт, добавляются детали, ярче свечение (тусклый PointLight или emissive), над башней номер уровня (canvas-спрайт).
- Модели башен (low-poly, ~50 полигонов каждая, больше деталей):
  - **Лёд** — основание-цилиндр + конус-шпиль с полупрозрачным материалом (opacity 0.85), 4 кристаллических шипа вокруг (TetrahedronGeometry, scale 0.2–0.3), ледяная корона наверху. L2: добавляются 2 шипа. L3: корона больше, emissive glow.
  - **Огонь** — основание-цилиндр с насечками (тонкие box-кольца), multiple flame cones (3 конуса разного размера, слоены), сверху дымоход-труба. L2: факел ярче, +дымовой шлейф. L3:agma-кольцо у основания, интенсивный glow.
  - **Молния** — основание-цилиндр + 4 шипастых проводника (конусы, торчат вверх), пульсирующий орб наверху (IcosahedronGeometry detail=1, emissive), катушки-кольца на стволе. L2: +2 проводника. L3: орб больше, ярче свечение.
  - **Яд** — основание-цилиндр + пузырящаяся сфера (SphereGeometry с noise-scale), крышка-гриб сверху, капли- «slime drip» (маленькие сферы на торцах). L2: пузыри больше. L3: крышка ярче, +токсичное свечение.
  - **Пушка** — механическое основание (цилиндр + шестерёнки-декор), ствол (двойной цилиндр: толстый + тонкий), дымоход сбоку, щит-пластина спереди. L2: ствол длиннее. L3: +бронепластины, ярче металл. Цвета: металл 0x666c76, тёмный 0x44404a.

**Палитра деталей (дизайнер):** лёд 0xbfe8ff (прозр. 0.85), огонь 0xff7a3c + пламя 0xffe08a, молния 0xffe95c, яд 0x5fd94f + тёмный 0x35502e, пушка 0x666c76. Range-ring (диск, зелёный 0x3ddc63, opacity 0.18) не путать со взрывными ring (цвет оружия, opacity 0.7→0).

### 2.6-1 Эффекты выстрелов (уникальные для каждого оружия)

**Заметка аналитика:** цель раздела — увеличить распознаваемость оружия визуально (по снаряду и взрыву понятно, какая башня стреляет) и усилить «фидбек» попадания. Логика/урон не меняются.

| Оружие | Снаряд | След в полёте | Вспышка при выстреле | Взрыв/попадание |
|--------|--------|---------------|----------------------|-----------------|
| **Лёд** | заострённая сосулька (конус/орость, светлый) | ледяные искры (частицы, бело-голубые, слегка замедленные) | короткая белая вспышка | иней: ледяные частицы + расширяющееся кольцо (ring, white), замедление видно по цвету |
| **Огонь** | огненный шар (сфера, оранжево-золотая, emissive) | раскалённый шлейф (оранжево-красные частицы) | вспышка пламени | огненный взрыв: конусы пламени + дым (серые частицы) + AoE-кольцо огня |
| **Молния** | светящаяся дуга (ломаная линия со случайными изломами) | искры-частицы вдоль дуги | вспышка на орбе | ветвящаяся молния (3–4 ответвления) + flash-вспышка |
| **Яд** | зелёная капля (сфера, emissive) | шлейф капель (зелёные частицы) | пузырь-вспышка | токсичное облако (купол зелёных частиц) + капли на землю |
| **Пушка** | тёмный снаряд (сфера, тёмно-серая) | дымовой след (серые частицы) | дымная вспышка + искры | ударная кольцевая волна (ring) + дым + разлетающиеся осколки |

- Взрыв при попадании масштабируется по размеру цели (босс — массивный, слизь — малый).
- Все эффекты используют пул частиц/переиспользуемые геометрии (без спама новых объектов в горячем пути).
- **Примечание системного аналитика:** новые геометрии (Tetrahedron, Triangle/плоскость крыла, Capsule) кешируются в `GEO` и помечаются `_cached` — не создавать на каждый спавн, disposeObj корректно их пропускает.
- **Снаряды:** `fireProjectile` выбирает геометрию/материал по `p.kind` из кеша (лед — конус-сосулька, огонь — сфера с emissive, яд — сфера, пушка — тёмная сфера; молния — line, без снаряда).
- **Взрывная волна (ring)** — отдельный пул эффектов `fxRings` (RingGeometry переиспользуемая, расширяется с затуханием opacity); для льда и пушки.
- **Дым/облако** — у частиц поле `grow` (медленный рост + всплытие + растворение opacity), серо-полупрозрачный материал; используется для огня (дым) и пушки.
- Общий пул линий/эффектов переименовывается из `fxLines` в `fxEffects` (линии молнии, кольца, дым) — один массив с переиспользуемыми объектами.
  - Элементы имеют поле `kind`: `'line'` (молния), `'ring'` (взрывная волна), `'smoke'` (дым); один update-цикл `updateFx` обрабатывает все три по `kind`.
- **Примечание разработчика:** крылья летуна/дракона: `PlaneGeometry` с `side: DoubleSide`, scale. Пузыри слизи кешируются в `GEO` и клонируются (`Object3D.clone`). Челюсть дракона — `parts.lowerJaw` из `group.children[3]`. Пульсация слизи через `parts.body.scale.y`, HP-бар не масштабируется. `resetGame` делает `clearGroup(sceneHas.fx)` — ок для всех эффектов в `sceneHas.fx`.
- **Примечание системного аналитика (проход 2):** дым/облако используют **один** переиспользуемый MeshBasicMaterial (серый полупрозрачный) на весь пул частиц; цвет/opacity задаются через свойства меша при активации, не плодим материалы на частицу.
- **Примечание тестировщика:** добавить smoke-тест в `runTests()` — вызов `buildTowerMesh(TOWERS[i], 1..3)` и `buildMonsterMesh(MONSTERS[i])` для всех 5+5 типов без WebGL не бросает исключений; повторный вызов не увеличивает число ключей в `GEO` (кеш работает). Частицы: при переполнении пула взрыв уменьшает `count` (graceful degradation), уникальных пулов для эффектов не плодим.
  - Дополнительно smoke-проверка анимационных ключей: для бегуна/гиганта существуют `parts.legL/legR` (+ руки `armL/armR`), для дракона — `parts.lowerJaw`, для летуна/дракона — `parts.wingL/wingR`. Сами повороты в updateMonster юнит-тестом не покрываются (нужен WebGL) — только «ключи есть».
- **Примечание дизайнера (проход 2):** `castShadow = true` только у наземных монстров (слизь, бегун, гигант) и только на основных частях тела; летуны и дракон летают — `castShadow = false` (не грузим теневую карту впустую). У башен тень — на основании/корпусе, не на мелких деталях.

### 2.7 Монстры (5 типов)

| Тип | HP | Скорость | Награда | Особенность |
|-----|----|----------|---------|-------------|
| Слизь | 40 | 1.0 | 6 | базовый |
| Бегун | 30 | 1.9 | 8 | быстрый |
| Гигант | 250 | 0.6 | 25 | броня: каждый удар −5 урона, мин 1 |
| Летун | 70 | 1.3 | 14 | летает на высоте 1.5, пушка по нему не стреляет |
| Дракон (босс) | 2000 | 0.45 | 200 | иммунитет к замедлению, яд 50% |

- HP с масштабированием волны: `hp = база × (1 + 0.10 × N)`.
- Скорость: с 20-й волны `+1% за волну`: `mult = N<20 ? 1 : min(1.6, 1 + 0.01×(N−19))` (на 20-й =1.01, кап 1.6 достигается к N≈79).
- Полоса HP над головой: тёмный фон + красная заполняющая часть, материал Sprite (биллборд к камере), пересоздаваться текстура только при изменении HP (не каждый кадр) — счётчик «грязных» обновлений.
- Анимации: покачивание при ходьбе (лёгкий наклон/взмах), летун машет крыльями (вращение пар плоскостей), дракон раскачивается.
- Модели монстров (ниже, см. 2.7-1):
  - **Слизь (Slime)** — полупрозрачная деформированная масса: сплюснутая сфера + 2-3 «пузыря»-шишки сверху. Анимация: пульсация `scale.y = 1 ± 0.05·sin(t·3)` и наклон. Глаза — белые сферы + чёрные зрачки, рот — маленький тёмный овал (плоский цилиндр). При движении — сжатие/растяжение вдоль направления (растягивается при ходьбе, сжимается при повороте).
  - **Бегун (Runner)** — антропоморфный: торс (вытянутая капсула/сфера, наклонён вперёд ~20°), 2 ноги-цилиндра с «беговой» анимацией (поочерёдный замах, rotation.x = ±40° вокруг поперечной оси), 2 тонкие руки (тоже машут), голова-сфера с заострённым рылом (конус-причёска). При движении бежит с наклоном корпуса.
  - **Гигант (Giant)** — **полностью антропоморфный**: голова (сфера) с 2 рогами (конусы, отклонены назад), торс (box 0.8×1.0, грудь шире пояса), 2 руки (плечо+предплечье бокс) с кулаками-сферами, 2 ноги (бедро+голень бокс, анимация шага rotation.x = ±15°), брюхо (сфера, выступает вперёд). Тяжёлые шаги: лёгкое раскачивание (rotation.z = ±2°), наклон корпуса вперёд.
  - **Летун (Flyer)** — тело-обтекатель (Icosahedron вытянутое), 2 крыла (TriangleGeometry/полуплоскость, машут rotation.x ±40°), хвост-стабилизатор (тонкий конус, сзади), клюв-конус, глаза. Покачивание на волне (rotation.z = sin(t)·0.05).
  - **Дракон (Dragon)** — антропоморфный босс: голова (сфера) с челюстью (2 бокса: верхняя/нижняя), зубы (мелкие конусы), рога (2 конуса, назад), глаза с glow (эмиссия); тело изогнутое (сфера+конус-грудь), крылья большие (плоскость с разрезом), хвост с шипом (конусы), 4 лапы (боксы). Анимация: взмах крыльев (±30°), раскачивание, челюсть открывается на ±15° при «дыхании».
- Движение: по точкам пути, следует к следующему вейпоинту, по достижении (дистанция < eps) переходим к следующему. Летуны — по прямой от входа до базы на высоте 1.5 (мимо карты).
- Смерть: разлетается частицами (пул), начисляется награда, убитых +1, текст награды.
- Дошёл до базы: исчезает, −1 жизнь (любой монстр, даже дракон), жизни в HUD обновляются мгновенно.

**Эффекты статусов:**
- Замедление (Лёд): коэффициент скорости ×0.6 на 2с (не стакается, обновляет таймер; дракону игнор).
- Горение (Огонь): 3 урона/с на 3с (по тику 1с). Дракону — 50% → 1.5/с? Спека работает: «яд 50%» про яд, у дракона «иммунитет к замедлению, яд 50%». Уточнение: дракон получает 50% урона от яда и игнорирует замедление. Горение применяется в полном объёме (не оговорено иначе).
- Яд: 5 урона/с на 4с, стак до 3 (независимые тики). Дракон: 2.5 урона/с (50%).

### 2.8 Волны
- Бесконечные. Индекс волны N начинается с 1. Первая стартует только по кнопке «Старт».
- Число монстров: `count = 6 + N×2`.
- Состав (функция `composition(N)`, реализуемая детерминированно):
  - N 1–3: только слизи.
  - N 4–6: слизи 70% / бегуны 30%.
  - N ≥ 7: доля гигантов = `min(0.20, 0.10 + 0.004×N)` (к N=25 → 0.20), доля бегунов 20% (не в 4–6 интервале — бегуны остаются в составе уже с 7-й).
  - N ≥ 10: доля летунов = `min(0.15, 0.10 + 0.003×N)`.
  - N ≥ 15: доля «тяжёлых» (гиганты) растёт: гиганты = `min(0.30, 0.10 + 0.006×N)`.
  - N кратно 10: боссы — `N<30 ? 1 : (N<50 ? 2 : 3)` драконов **плюс** обычный состав волны.
  - Доли применяются к `count` с `floor`/`round` и остаток добирается слизями так, чтобы итог = `count`.
  - Порядок: список перемешивается (детерминированный shuffle с seed= N), затем «тяжёлые» (гиганты, драконы) перемещаются в последнюю треть очереди, сохраняя относительный порядок.
- Интервал появления: **0.7с**.
- Между волнами: **12с** обратного отсчёта (ускоряется множителем скорости). Кнопка «Следующая волна» запускает следующую немедленно.
- Масштаб HP монстра применяется с учётом N волны, в которой монстр появился.

### 2.9 Жизни и конец игры
- 20 жизней. Отображаются в HUD.
- Жизни = 0 → модальное окно «Игра окончена»: показать волну, убитых, заработано (сумма наград). Кнопка «Играть снова» — полный сброс (карта перестраивается, деньги/волна/башни/монстры/счётчики обнуляются). Игровой ввод во время модалки заблокирован.

## 3. Пользовательские сценарии (UX-флоу)

1. Открыть файл → стартовый экран: **название текущей карты** (случайно выбранной), кнопка «Старт», подсказки (2–3 строки).
2. Клик «Старт» → экран игры, волна 1 не стартует до клика «Следующая волна»? Нет: кнопка «Старт» сама запускает волну 1 с обратным отсчётом/немедленно. **Решение:** «Старт» скрывает стартовый экран и запускает волну 1 (countdown 12с с можливостью ускорить кнопкой). Принято, консистентно с «Первая волна стартует только по кнопке "Старт"».
3. Игрок строит башни: клик по пустому слоту → панель с 5 карточками (иконка-эмодзи/мини-3D, название, цена, описание). Недоступные по деньгам — серые/некликабельные. Клик по карточке → строится башня, деньги списываются. Клик мимо панели → панель закрывается, кольцо дальности снимается.
4. Недостаточно денег для всех карточек → карточки серые; призрака нет, пока карточка не выбрана.
5. Игрок наводит на построенную башню → кольцо дальности. Клик → панель управления: название, «Уровень X из 3», характеристики (урон/дальность/скорострельность), кнопка «Улучшить (цена)» — серая при нехватке денег или на 3 уровне, кнопка «Продать (+сумма)». Крестик и клик мимо закрывают.
6. Монстры идут по дороге, башни стреляют, награды всплывают, счётчики меняются.
7. Контроль: Пробел — пауза, кнопки пауза/продолжение и скорость 1x/2x в HUD.
8. Между волнами — обратный отсчёт, кнопка «Следующая волна» ускоряет.
9. 0 жизней → «Игра окончена» → «Играть снова» → полный сброс, снова стартовый экран? **Решение:** кнопка «Играть снова» сразу рестартит игру (стартовый экран с названием не обязателен — рестарт показывается мгновенно в игровом состоянии с фазой «ожидание волны 1», без показа меню). Это консистентно со спекой «полный сброс».

## 6. Архитектура и техническое решение

### 6.1 Структура файла `index.html`
1. `<!DOCTYPE html>` + `<head>`: meta viewport, `<title>`, `<style>` (весь CSS: HUD, панели, модалки, media queries).
2. `<body>`: `<div id="app">` с `<canvas>` (Three.js рендерит в него) + HTML-слой UI (`#hud`, `#build-panel`, `#tower-panel`, `#start-screen`, `#gameover`, `#range-ring` не нужно — кольцо в 3D).
3. `<script type="importmap">` (three + three/addons jsdelivr r184).
4. `<script type="module">` с кодом игры.

### 6.2 Кодовая структура внутри модуля (секции)
- Импорты, константы (типы башен, монстров, формулы).
- `state` — единый объект игры.
- Инициализация рендера/сцены/камеры/света/контролей.
- Построение карты (земля, дорога, база, портал, слоты, декорации) — по статичным данным карты.
- Системы путей (список вейпоинтов, `progressPath`).
- Фабрики моделей (башни по типу/уровню, монстры по типу, снаряды, частицы, HP-бары, числа).
- Монстры: спавн, движение, статусы, смерть, утечка.
- Башни: таргетинг, вращение, стрельба, снаряды, AoE/цепь/статусы.
- Волны: `composition(N)`, спавн по таймеру, определение конца волны.
- Экономика: покупка/улучшение/продажа, награды.
- UI: функции обновления HUD (вызываются по событиям изменения), панели, модалки.
- Ввод: raycast по указателю (hover/click), клавиши (Space, 1-5? — не обязательно, только Space).
- Эффекты: частицы, всплывающие числа, молния-линия.
- Главный цикл `loop(timestamp)`: dt → game.dt′ = dt × speed; обновление монстров, башен, снарядов, частиц, волн, анимаций; рендер.
- `resize`, сброс/рестарт, утилиты (сеяный генератор, оверрайд диспоуза).

### 6.3 Данные (константы)
- `TOWERS` — массив из 5 типов (base и таблица уровней по формулам).
- `MONSTERS` — 5 типов (база).
- `MAPS` — массив из 3 объектов (id, name, roadCells, slotCells, pathWaypoints, start, end); `game.currentMap` — текущая (выбранная случайно).
- `PATH`, `PATH_LENGTH`, `FLY_PATH`, `FLY_LEN` — вычисляются из `game.currentMap` при смене карты.

### 6.4 Ошибки и edge cases
- Не хватает денег → кнопки/карточки недоступны, покупка/улучшение заблокированы (без «покупки в минус»).
- Продажа единственной башни → деньги возвращаются, слот свободен, кольцо/панель закрываются.
- Улучшение на 3 уровне → кнопка неактивна.
- Слот наведён → зелёная/красная рамка; занятый слот при наведении не показывает зелёную.
- Снаряд летит в цель, которая умерла → снаряд летит в последнюю позицию цели и взрывается там; если цели нет на карте — уничтожить снаряд без взрыва.
- Цель вышла из радиуса → перевыбор цели на следующем такте.
- Летуны вне досягаемости пушек: пушка не выбирает летунов целью вовсе.
- Пауза (speed=0): не спавнятся волны, не двигаются монстры, таймеры стоят, UI жив. Повторный Пробел — продолжить.
- Перезапуск: полная очистка сцены (traverse и dispose), пересоздание карты, обнуление состояния.
- Ресайз во время игры не влияет на логику (только камера/рендер).
- Монстры не «срезают» углы за пределы дороги: ведём по центральной линии (вейпоинты сглажены прямыми отрезками, повороты резкие через центр клетки).
- Спавн волны во время паузы: таймеры масштабируются dt×speed, на паузе заморожены, при снятии паузы продолжают корректно.
- При утечке последнего монстра волны — конец волны и обратный отсчёт (флаг состояния).
- Драг-босс: иммунитет к замедлению; яд 50%; брони нет.
- Гигант: броня применяется к каждому попаданию (и к тикам яда/горения тоже — единое правило для любого источника урона), min 1.

### 6.5 Оптимизация производительности
- Геометрии и материалы кешируются по типу (карта: башня/монстр/снаряд/частица → общий экземпляр).
- Пулы частиц (N=200) и снарядов (N=100) с переиспользованием, удаление из сцены при неиспользовании.
- HP-бары пересоздаются только при изменении значения (нет тиков на каждый кадр).
- Соло-каст DirectionalLight; остальные эффекты без теней (объекты не требуют индивидуальных теней, кроме критичных).
- `renderer.setPixelRatio(min(dpr,2))`, туман — лёгкий.
- Не создавать объекты в цикле горячих путей без переиспользования.

## 7. UX/UI и responsive (Дизайнер)

### 7.1 Слои и состояния
Слои (z-порядок): canvas (3D) → HUD (верх) → контекстные панели → стартовый/гейм-овер экран (поверх).
Состояния экранов: `start` → `playing` → (пауза — флаг) → `gameover`. Панели — независимые оверлеи над gameplay.

### 7.2 HUD (верхняя панель)
Полупрозрачная тёмная полоса (backdrop-filter blur, rgba). Слева направо:
`💰 деньги` | `❤ жизни (из 20)` | `🌊 волна N` | `☠ убито` | `👺 осталось в волне` | `⏱ отсчёт 12с / кнопка "Следующая волна"` | `⏸/▶ пауза` | `1x/2x скорость`.

### 7.3 Панель постройки (клик по пустому слоту)
Маленькая плавающая карточка рядом со слотом (новое положение — возле слота, clamp в экран): 5 кнопок-карточек: иконка (эмодзи или мини-canvas), название, цена, описание. Недоступная — сниженная прозрачность, курсор no-drop, клик игнорируется.
При открытии панели показывается призрак выбранного типа + кольцо дальности на земле под слотом (если карточка выбрана). Клик по самой карточке строит башню (мгновенно, панель закрывается).

### 7.4 Панель управления башней
Плавающая карточка рядом с башней (clamp в экран): название башни, «Уровень X из 3», параметры (урон, дальность, скорострельность текущего уровня), кнопка «Улучшить — 80🪙» (серая если не хватает или макс.), кнопка «Продать +130🪙», крестик в углу.

### 7.5 Стартовый/гейм-овер экраны
Полноэкранные оверлеи с затемнением. Стартовый: заголовок, 3 строки подсказок, кнопка «Старт». Game over: «Игра окончена», волна/убито/заработано, кнопка «Играть снова».

### 7.6 Responsive (Desktop / Tablet / Mobile)
- Базовая ширина вёрстки — гибкие блоки с max-width, min-width, flex-wrap.
- HUD: на Desktop одна строка; на узких экранах (`<720px`) переносится на 2 строки (flex-wrap), шрифты слегка уменьшаются (clamp()).
- Панели: `max-width: min(92vw, 420px)`, рамки, автоцентрирование; на Mobile панель позиционируется по центру снизу/вниз экрана (не рядом со слотом — clamped).
- OrbitControls на touch: вращение 1 пальцем, зум пинчем — включено по умолчанию.
- Никаких абсолютных отступов в пикселях для сетки UI (используются flex/grid + margins на основе rem/em).
- Проверка на 1280×720 (Desktop), 768×1024 (Tablet), 390×844 (Mobile).

### 7.7 Доступность/качество
- Русская локаль во всех строках.
- Кнопки — крупные, с подписями и value; focus-рамки не требуются (игра на мышке), но кнопки реагируют на `:hover`/`:active`.

## 8. Зависимости и интеграции
- Полностью офлайн после загрузки страницы: единственная сетевая зависимость — три CDN (three r184 модуль + addons).
- Игра не зависит от файловой системы, кроме самого `index.html`.
- Интеграция «canvas ↔ DOM UI»: кадрирование панелей по позиции слота в координатах экрана (проекция вектора `Vector3.project(camera)` → CSS px, clamp к вьюпорту). При повороте камеры панель пересчитывается каждый кадр, пока открыта.

## 9. План реализации (Разработчик)

### 9.1 Базовая игра
Ориентировочный объём: ~1500–1800 строк в одном файле. Порядок:

5. Башни: модели 3 уровней, таргетинг, вращение, снаряды, спецэффекты (замедление/AoE+горение/цепь/яд/взрыв).
6. Экономика + покупка/улучшение/продажа + панели + кольца + призрак.
7. HUD, стартовый экран, game over, рестарт, пауза, скорость.
8. Эффекты: частицы, всплывающие числа, молния.
