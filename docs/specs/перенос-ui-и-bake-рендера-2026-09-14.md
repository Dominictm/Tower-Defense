## 1. Цель и ожидаемый результат

Перенести в `D:\game\index.html` проверенный UI-скелет и техники графики из
прототипа `tower-defense-astra.html` (CDN-прототип той же игры, баланс совпадает,
99% разницы — оформление). Итог — «продакшн»-интерфейс: постоянный док-бар башен,
инспектор башни, диалог-справка, тосты, SVG-иконки, событийный HUD, улучшенный
responsive и bake-рендер (1 draw call на юнита) для производительности.

**Ожидаемый результат:** `index.html` получает новый UI и bake-графику; геймплей,
баланс, карты, механики, формулы и экономика **не меняются**; все автотесты проходят
(с адаптацией модельных smoke-тестов к bake-структуре).

## 2. Функциональные требования

### 2.1 Что переносим из astra (UI)
1. **Topbar** (фиксированный верх): слева — бренд/заголовок игры; центр — блок
   статистики (💰 Монеты, ❤ Жизни, 🌊 Волна, ☠ Побеждено, 👺 Осталось); справа —
   кнопки: Пауза, Скорость ×1/×2, Справка.
2. **Command-bar** (фиксированный низ): слева контекстная подсказка («Выберите
   площадку или башню»), справа статус волны + кнопка «Начать волну / Следующая
   волна»; под ним **dock** из 5 карточек башен (иконка, короткое имя, тег, цена).
3. **Інспектор башни** (фиксированный по центру справа): уровень «X / 3», название,
   описание, блок атрибутов (УРОН / РАДИУС / В СЕК.), кнопка «Улучшить — N🪙» и
   «Продать за M🪙», крестик закрытия. Открывается по клику на построенную башню.
4. **Диалоги** через нативный `<dialog>` + `showModal()`: game-over (волна, побеждено,
   заработано, «Играть снова») и справка «Как защитить…» (механики + клавиши).
   Закрытие по «Всё понятно»/крестику/Esc; фокус переходит на первичную кнопку.
5. **Toast** (фиксированный верхний центр): событийные сообщения, автоскрытие ~3 с.
6. **Footer-hints**: подсказки мыши/клавиатуры (desktop) и касаний (mobile), выбор
   брейкпоинтом; `pointer-events: none`.
7. **Призрак башни + кольцо дальности** при наведении на свободный слот и при
   выбранном типе — сохраняется текущее поведение (уже реализовано в index.html).
8. **Всплывающие награды/урон** (`#floaters`) и **HP-бары** над монстрами — остаются
   как есть (CSS div поверх 3D, проекция через `Vector3.project(camera)`).

### 2.2 SVG-иконки башен
- 5 векторных иконок стихий (лёд/огонь/молния/яд/пушка) в единой «платформенной»
  рамке (трапеция-пьедестал + форма стихии), стиль — из astra (`icon()`).
- Размеры иконок: ~50×66 в dock (desktop), уменьшаются на mobile.
- Иконки генерируются из JS-функции (inline SVG), не внешние файлы.
- Цвета иконок берутся из текущих палитровых значений `TOWERS[].color`
  (добавляется `css`-hex-поле в `TOWERS`, как в astra).

### 2.3 Bake-рендер (перенос техники astra)
1. **worldMat**: один `MeshStandardMaterial({ vertexColors: true, flatShading: true,
   roughness: 0.95 })` для всех статичных запеченных мешей.
2. **bake(group)**: пройтись по Group из примитивов → собрать переиндексированную
   геометрию с `setAttribute(position|normal|color)` → один меш = 1 draw call.
3. **Кеши запеченных геометрий**:
   - `towerGeo` — по `type + level` → отдельно статичное «основание» и анимируемая
     «верхушка» (вращающаяся пушка у cannon), кеш переиспользует меши.
   - `actorGeo` — по типу монстра: статичное тело запекается целиком; анимируемые
     части (конечности через `legPivot`/`limbPivot`, крылья `wingMesh`, нижняя
     челюсть дракона) НЕ включаются в bake статики — они остаются отдельными
     запеченными мешами на pivots (как астра крылья), чтобы не сломалась текущая
     анимация (`parts` в userData сохраняется).
   - мир: поле/дорожка/декор/слоты/база/портал запекаются в 1–2 меша на карту,
     кеш по `currentMap.id`; подсветка слотов (highlight), range-кольца, призрак —
     отдельно, в bake НЕ включаются.
4. **Материалы уровня башен**: база — `worldMat`; верхушка — кэшированный материал с
   `emissive` = фирменный цвет типа + `emissiveIntensity` от уровня (как astra).
5. **Particle pool → InstancedMesh** (200 частиц, базовая геометрия + белый
   `MeshBasicMaterial`, пер-инстанс цвет через `setColorAt`). Вместо 200 отдельных
   Mesh (текущий `buildParticlePool`) — 1 draw call.
6. **Призрак башни**: вместо примитивов (`geoCyl`+`geoCone`) — запеченная модель
   башни уровня 1 с клоном `worldMat`, прозрачной, `depthWrite: false` (как астра
   `preview`), + оранжевый ring/rangeFill используются текущие.
7. **Снаряды/fxEffects** (молнии-линии, кольца, дым) — не bake; остаются в текущем
   пуле `fxEffects` (небольшое число объектов).
8. **Производительность**: существенное снижение draw calls; FPS-смоук (60 монстров,
   5+ башен) — не ниже 50 FPS.

### 2.4 Что НЕ переносим (границы)
- **Камера**: остаётся `PerspectiveCamera` + `OrbitControls` (решение пользователя).
- **Тема/брендинг**: нейтральная «Tower Defense 3D» (без «Лесного рубежа»,
  Georgia, щита, eyebrow-подписей, ауры леса). Переносим структуру и поведение, не
  стилистическую тему. Шрифты/цвета UI берём от текущего HUD (тёмные полупрозрачные
  панели, акцент `#2f9e4f`, золото `#ffd94a` для цен).
- **Механики и баланс**: 5 башен × 3 уровня, 5 монстров, волны `6+N×2`, HP-кривые,
  награды, цены, таргетинг, броня, цепь молнии, пул частиц — без изменений.
- **Карты и палитра PALETTE** 3-й итерации — без изменений.
- **Ортокамера, кастомные жесты поворота, pinch** astra — не переносим
  (OrbitControls уже поддерживает touch).
- Перф-оптимизация «bake» НЕ распространяется на урон/статы/логику.

## 3. Пользовательские сценарии (UX-флоу)

1. Старт: оверлей с заголовком, названием карты, 3 подсказками, кнопка «▶ Старт».
2. Игра: topbar (статы + кнопки), внизу dock с 5 башнями. Клик по свободному слоту →
   слот подсвечен, команда «Выберите башню внизу экрана»; клик по карточке башни —
   строится сразу (деньги списываются), либо (если карточка выбрана ранее) призрак +
   кольцо дальности, повторный клик по слоту строит.
   Клик по построенной башне → инспектор справа (уровень, статы, улучшить/продать).
3. Клик по траве/дороге → снять выделение и кольцо.
4. Кнопка «Начать волну» в command-bar; статус волны обновляется событийно.
5. Пауза (Пробел/кнопка), скорость ×1/×2 (кнопка), справка (кнопка «?» → dialog),
   game-over → dialog с результатами → «Играть снова» мгновенный рестарт.
6. Esc — снять выделение; R — вернуть камеру; 1-5 — выбрать башню (при орбите).

## 5. Затрагиваемые модули
- UI: CSS (`<style>`), HTML-разметка (`#hud` → topbar+command+dock+inspector+footer),
  JS: `updateHUD` → событийный `updateUI`, новая `toast()`, диалоги, SVG-иконки.
- Ввод: raycast по слотам (`getSlotAtScreen`) остаётся; `#build-panel`/`#tower-panel`
  (плавающие панели) **удаляются** — заменяются dock + inspector. `positionPanel`/
  `screenPos` остаются только для floaters? — нет, floaters используют `addFloat`,
  `positionPanel` удаляется, `screenPos` больше не нужен.
- 3D: `buildTowerMesh`, `buildMonsterMesh` → bake + clip части; `buildMap` (мир) →
  bake по карте; `buildParticlePool` → InstancedMesh; призрак → bake-L1-клон; база/
  портальные меши остаются как есть (небольшое число объектов).
- Тесты: `runTests()` (модельные smoke-тесты адаптируются под bake), добавляются
  UI-проверки DOM (наличие topbar/dock/инспектора/диалогов).

## 6. Ограничения и риски
- **Регрессия модельных тестов**: тесты `children.length > 3` и пересчёт castShadow
  сломаются при bake (1 меш). Тесты необходимо переписать на правила bake-структуры
  (см. §10), сохранив инвариант «GEO/кеш стабилен».
- **Анимации**: bake объединяет статику; все анимируемые части выносятся в отдельные
  пивоты до bake — риск пропустить деталь, анимация «умрёт» незаметно. В тестах —
  проверка наличия пивотов у runner/giant/dragon.
- **DOM-mock (verify-models.cjs)**: bake использует `geometry.toNonIndexed()`,
  `applyMatrix4`, `getAttribute`/`setAttribute`, `index`, `toNonIndexed`,
  `Float32BufferAttribute`, `computeBoundingSphere`; InstancedMesh + `setMatrixAt`/
  `setColorAt`/`instanceMatrix`. Мок в test-harness'e нужно расширить этими API
  (заглушки возвращают корректные структуры), иначе тесты словят TypeError.
- **Перф**: двойные запекания на старте (периодический build при рестарте карт) —
  кеш по `currentMap.id` и по `type+level` минимизирует работы.
- CDN остаётся единственной сетевой зависимостью (нет новых библиотек).

## 7. UX/UI и responsive (Дизайнер)
### 7.1 Слои и состояния
z-порядок: canvas → floaters (награды) → topbar → command/dock → inspector →
toast → dialogs (game-over последний). Состояния как сейчас: start → intermission
→ wave → gameover; панели — независимые оверлеи.

### 7.2 Topbar (верх)
Фиксированный верх, flex, wrap на <720px. Слева бренд/название игры + (на mobile
только заголовок), центр/свободное — статистика (5 статов: 💰❤🌊☠👺), справа
кнопки: пауза, скорость ×1/×2, справка «?».
- Desktop одна строка; Mobile: строка1 — бренд + кнопки, строка2 — статистика
  (flex-wrap, `justify-content: space-around`).

### 7.3 Command + dock (низ)
Command-бар: контекстная подсказка слева, справа статус волны + кнопка
«Начать волну/Следующая волна». Под ним dock из 5 карточек (иконка+короткое имя+
цена). Mobile: hint прячется/кратко, кнопка волны компактнее, dock — grid в 5
колонок.

### 7.4 Инспектор башни (справа по центру)
Карточка: уровень «X / 3», название, описание, атрибуты (урон/радиус/в сек.),
кнопки «Улучшить — N🪙» (disabled на max/нехватке) и «Продать +M🪙», крестик.
Desktop — справа по вертикальному центру; Mobile — снизу по центру;
`background: var(--panel)`, `border-radius`, `backdrop-filter`.

### 7.5 Диалоги
Нативные `<dialog>` (game-over, справка): заголовок, абзацы, первичная кнопка с
фокусом, закрытие Esc/кнопка «×»/«Всё понятно». `dialog::backdrop` затемнение.

### 7.6 Toast / подсказки
Toast — верхний центр, автоскрытие 3 с, `aria-live=polite`, на mobile max-width
90vw, перенос текста. Footer-hints: desktop-подсказки (мышь/клавиатура) и
mobile-подсказки (касание/свайп/пинч), выбор брейкпоинтом, `pointer-events:none`.

### 7.7 Responsive
- Брейкпоинты: ≥1600 (шире welcome/команда), >1100, ≤760 (mobile-компоновка),
  `max-height:580` (компактный ландшафт).
- Базовые правила: никаких абсолютных пикселей в сетке UI — flex/grid; gap/отступы
  на em/rem; тап-таргеты ≥34px; `touch-action: manipulation` на кнопках; шрифты — `clamp()`.
- Проверка: 1280×720 (Desktop), 768×1024 (Tablet), 390×844 (Mobile).
- `prefers-reduced-motion: reduce` — отключение анимаций (как astra).

### 7.8 Доступность
- `aria-label` на иконках/кнопках, `role=status` на тосте, disabled-состояния,
  фокус на первичной кнопке диалога, клавиши: Space (пауза), 1–5 (выбор башни),
  Esc (отмена), R (камера) — из astra, с сохранением текущих хоткеев.

## 8. Зависимости и интеграции

## 10. Feature Tests / UI Tests (черновик → Тестировщик)
- Все существующие арифметические/карт-сценарии остаются (правила не менять).
- Модельные smoke-тесты переписываются: `buildTowerMesh(type,lv)` возвращает объект с
  запеченным мешем (1 base mesh+1 turret pivot), castShadow на корневых мешах;

  `userData.parts` (как сейчас), их наличие проверяется тестом.
- UI-проверки (в `?test=1`, DOM-mock): существуют `#dock`, 5 `.tcard`, `#inspector`,
  `#gameover-dialog`, `#help-dialog`, topbar-статы; `toast()` добавляет `.show`.
- Ручной чек-лист responsive 3 экранов + консоль без ошибок; FPS-смоук ≥50 FPS.
- Расширение DOM-mock: bake API геометрий и InstancedMesh (см. §6).

## 11. Тестовые данные

## 12. Критерии приёмки
1. index.html: только файл игры; запуск двойным кликом; стартовый оверлей с картой.
2. Консоль без ошибок в обычной игре и `?test=1`; `TEST PASS` по всем сценариям.
3. Новый UI: topbar, dock, инспектор, диалоги, toast, footer-hints — реализованы и
   работают (ручной чек-лист на Desktop/Tablet/Mobile).
4. Регрессия: 3 карты играбельны; волны/баланс/экономика без изменений.
5. Bake-профрит: видимый рост FPS-смоука (60+ монстров, 5+ башен) ≥50 FPS;
   кеши bake стабильны (тест).
6. Анимации башен/монстров (крылья, конечности, челюсть, поворот пушки) работают.

- **Финальный аналитик**: спека согласована, противоречий между геймплеем, UI,
  bake и тестами нет; критерии приёмки покрывают все разделы.
