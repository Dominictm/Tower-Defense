## 1. Цель и ожидаемый результат

Поднять визуальное качество low-poly сцены: больше геометрической детализации (сглаживание, сегментация, составные детали) и осознанная цветовая композиция с ролями палитры. Дизайн остаётся low-poly, но перестаёт быть «плоским и одноцветным».

Ожидаемый результат: карта (трава, дорожка, база, портал, декорации), башни и монстры читаются чётче, выглядят насыщеннее и живее; фирменные цвета типов сохраняются.

## 2. Функциональные требования

### 2.1 Детализация геометрий (общий кеш `GEO`)

Увеличить разрешение примитивов в фабриках геометрий (не менять ключи кеша — только параметры конструкторов):

| Функция | Сейчас | Стало |
|---------|--------|-------|
| `geoSphere` | `SphereGeometry(0.5, 12, 8)` | `SphereGeometry(0.5, 16, 12)` |
| `geoCone` | `ConeGeometry(0.5, 1, 10)` | `ConeGeometry(0.5, 1, 14)` |
| `geoCyl` | `CylinderGeometry(0.5, 0.5, 1, 12)` | `CylinderGeometry(0.5, 0.5, 1, 16)` |
| `geoIco` | `IcosahedronGeometry(0.5, 0)` | `IcosahedronGeometry(0.5, 1)` |
| `geoCap` | `CapsuleGeometry(0.35, 0.6, 4, 8)` | `CapsuleGeometry(0.35, 0.6, 6, 12)` |

- Требование: суммарный прирост полигонов не должен деградировать FPS при 60+ монстрах (см. §14.3 и критерии приёмки).
- Переиспользование (`g()`-кеш) сохраняется; ключи не меняются → smoke-тест «кеш не растёт» остаётся зелёным.
- Новые вспомогательные геометрии (фаски, детали) тоже кешируются в `GEO`.

### 2.2 Поле (трава)

Заменить плоский зелёный куб-«стол» на волнистую «местность»:

- Поле: `PlaneGeometry(16, 12, 16, 12)` с детерминированным смещением вершин по Y (`y = 0.03·sin(x·1.7)·cos(z·1.3)` + шум на seed карты), `flatShading` для граней.
- Цвет: не сплошной, а 3 близких тона травы (база / пятна / кайма), см. §2.6.
- **Важно:** волны поля не должны поднимать уровень выше проезжей части — дорожка и слоты лежат «поверх» (сравнимо с текущей высотой 0.08/0.06). Смещение вершин делать **вниз**-ориентированное (max ~0.04) или центр поля держать на 0 и уводить к краям — проверка в §14.1.
- Тени/стенки: сохранить тонкий боковой «бордюр»-коробку под всём полем (как сейчас), чтобы не просвечивало мирами сбоку.

### 2.3 Дорожка (секции-плиты)

Заменить единый песочный блок на сегментированную дорогу из плит:

- По каждой клетке дороги — плита `geoCube()` scale `(x=1.0, y=0.08, z=1.0)` цвета «песчаник база».
- **Скос кромки:** по периметру каждой плиты 4 тонких скоса-«бордюра» (маленькие утолщённые кубы или приподнятые T-образные фаски) цвета «песчаник тень» — читаются как швы между плитами.
- Дополнительный акцент: диагональные трещины/швы — через тёмные тонкие кубики вдоль стыков (случайность на seed карты).
- Вход (портал) и база остаются на концах дороги (§2.5 становится детальнее, см. 2.5).
- Требование: количество мешей дороги = число клеток × (1 + 4 скоса) ≤ ~300 мешей суммарно по всем объектам карты — в пределах нормы для статики (см. производительность).

### 2.4 Слоты башен

- Плитки слотов — с тонкой светлой окантовкой (как сейчас), но с лёгкой «приподнятостью» (сравнимо с текущей), чтобы отличаться от дорожных плит по тону (§2.6: «плита» — светлый, отличный от песчаника).
- Скошенные кромки слотов — светлее, чем у дороги (роль «плита/интерактив»).

### 2.5 База и портал (детализация)

- **База (замок с 4 башнями — реализовано в итерации 2):** добавить цветовые акценты: каменная база/тёмный камень, крыши-конусы, флаг; каменные швы по белому камню.
- **Портал:** кольцо-торус контрастным цветом роли «магия» + тёмный входной диск; лёгкое свечение (emissive) — статичный пульс не требуется.

### 2.6 Цветовая композиция (палитра ролей)

Ввести роли палитры (константы `PALETTE`):

| Роль | Цвет | Применение |
|------|------|------------|
| `grassBase` | 0x6bbf4a | база поля |
| `grassPatch` | 0x5aa840 | пятна травы (модули, детерминированно) |
| `grassEdge` | 0x7cc95a | кайма/осветлённые участки у дороги |
| `roadBase` | 0xd9b380 | плиты дорожки |
| `roadDark` | 0xb8895a | скосы/швы дорожки |
| `slotBase` | 0xe8e4c8 | плитки слотов |
| `towerWarm` | 0xa06a4a | керамика/камень тёплых башен (огонь/яд/пушка) |
| `towerCool` | 0x7f9fc9 | камень холодных башен (лёд/молния) |
| `stoneDark` | 0x54525e | тёмные вставки/швы |
| `magicAccent` | 0x7b4aa8 | магия портала/базы |
| `skySoft` | 0xcfe8ff | скай (приглушить с 0xbfe3ff) |

- **Тёплые/холодные семьи:** башни-типы сохраняют свои фирменные акценты (лёд 0x79cfff, огонь 0xff7a3c, молния 0xffe95c, яд 0x5fd94f, пушка 0x999ea8) — вводятся только нейтральные «корпуса» двух семей.
- **Враги:** холодная гамма, у каждого монстра сохраняется фирменный цвет (не перекрашивать). Добавить тёмные окантовки (глаза/рот уже тёмные).
- **Скай/фон:** `scene.background` 0xbfe3ff → 0xcfe8ff (мягче, меньше сливается с холодными юнитами); fog синхронно.
- Пятна травы/скосы генерируются детерминированно на seed карты (соответствует текущей детерминированности декораций).

### 2.7 Башни (детализация)

- **Основание:** гексагональная плита (шестигранный цилиндр `CylinderGeometry(r, r, 0.10, 6)`) цвета `towerWarm`/`towerCool` по семье → не сфера-цилиндр.
- **Кольца-перила:** 1–2 `TorusGeometry` вокруг ствола на разных уровнях (кешируются), материал тёмного металла/камня.
- **Каменные швы:** тонкие тёмные кольца (цилиндры высотой ~0.02, тёмного цвета) между секциями корпуса — подчёркивают «сложенность».
- Сохранить уникальные завершения по типу (шпиль льда, пламя, орб молнии, пузырящаяся сфера яда, ствол пушки) — см. СПЕКА §2.6.
- Уровни L2/L3: надбавка деталей (дополнительные кольца/шипы) сохранить и подкрасить тёмными швами — прирост виден.

### 2.8 Монстры (детализация)

- Детализация за счёт новых сегментов/ложных деталей, цветовые акценты тёмными краями (глаза, когти, шипы уже есть).
- Гиганту: добавить «нагрудник»-пластину (светлее тон) — не менять силуэт и размер.
- Дракону: контраст чешуи (2-3 чуть светлее вставки на теле), сохранить glow-глаза.
- Летуну/слизю: блестки-вставки не добавлять; только улучшенная геометрия от §2.1.
- Требование: не менять физические размеры, scale, HP-бары, точки крепления анимации (`parts`).

### 2.9 Декорации

- Сосны: крона из 2–3 конусов (вместо одного), цвета зелени с вариацией тона на seed.
- Кусты: 2–3 пересекающиеся сферы вместо одной.
- Камни: `geoIco` детализированный, 2–3 гранёных варианта, серые тона.
- Холмы: лёгкие выступы (сглаженная сфера снизу), не мешающие слотам/смотру.

## 6. Архитектура и техническое решение

- **Константа `PALETTE`** (объект с цветами ролей §2.6) — рядом с `TOWERS`/`MONSTERS`.
- **Геометрии:** правки только в фабриках §2.1 (параметры конструкторов) + новые фаски/кольца кешируются через `g()`.
- **Поле:** в `buildMap()` заменяется «стол» (box) на `PlaneGeometry` + генератор волн (чистая функция `waveY(x, z, seed)`); пятна — разметка плоскостей-«заплаток» или вершинные цвета; боковины-обшивка остаются.
- **Дорожка и слоты:** цикл по клеткам карты строит плиты + скосы (общие геометрии/материалы по ролям).
- **Башни/монстры:** в `buildTowerMesh`/`buildMonsterMesh` добавляются новые детали через существующие контейнеры; ключи `parts` не меняются (анимации сохранны).
- **Детерминизм:** волны поля, пятна и декор считаются от seed карты; при рестарте той же карты — тот же вид.
- **dispose:** новые геометрии помещаются в `GEO` (помеченные `_cached`); `disposeObj` пропускает кешированные — без утечек.

## 7. UX/UI и responsive

## 9. План реализации (порядок)

1. Константа `PALETTE` + подключение в существующие места (grass→grassBase и т.д.).
2. Фабрики геометрий: параметры детализации §2.1 → проверка smoke-теста кеша.
3. Поле: плоскость+волны+пятна+боковины, обновить `dispose`/`resetGame`.
4. Дорожка: плиты+скосы по клеткам; слоты, база, портал (§2.4–2.5).
5. Башни: гекс-основания, кольца, швы (§2.7).
6. Монстры: акценты (§2.8), декорации (§2.9).
7. Свет/фон: скай 0xcfe8ff, fog.
8. Автотесты: `?test=1` — 681/681 PASS; smoke-тест «кеш GEO не растёт»; **проверка высот слотов/дорожки vs волны поля** (выпуклости не выше слотов в ячейках слотов).
9. Ручной визуальный чек-лист (§14.3) + FPS-смоук.

## 10. Тестирование

### 10.1 Feature Tests (авто, харнесс `?test=1`)

- Все существующие 681 теста проходят (логика не изменена).
- Новые smoke-ассерты:
  - `waveY` детерминирован для (x, z, seed): два вызова = одинаковые значения; `max |waveY| < 0.05`.
  - В ячейках слотов и дороги `waveY ≤ 0` (не задирает плиты выше бортика) — тест в рамках карт (3 шт.).
  - Повторный `buildMap()` (и 2-й `resetGame`) не увеличивает количество ключей в `GEO` (кеш).
  - `buildTowerMesh` для 5 типов и 3 уровней без WebGL не бросает исключений (расширение существующего smoke-теста деталей).
  - `PALETTE` содержит все роли §2.6 (уникальные ключи).

### 10.2 UI Tests (ручной чек-лист)

- Игра запускается, стартовый/гейм-овер экраны, HUD — в прежнем виде.
- Карта: трава с пятнами и волнами; дорожка сегментированная; база/портал детальнее.
- Постройка/улучшение/продажа: внешний вид изменился корректно; кольца и панели читаемы поверх нового рельефа.

## 11. Тестовые данные

- Seed карты: 3 фиксированных (classic/zigzag/arc) — как в текущем коде.
- Эталон: максимальная амплитуда волны `waveY` ≤ 0.04.

## 12. Критерии приёмки (Definition of Done)

1. Сцена визуально детальнее и «живее» относительно итерации 2: геометрии сглажены, поле волнистое с пятнами, дорога сегментирована, башни с гекс-плитой/кольцами/швами, декор составной.
2. Цветовые роли читаются: тёплая семья башен, холодная — врагов, фирменные акценты типов сохранены; скай приглушён.
3. Повторный старт одной и той же карты даёт идентичный внешний вид (детерминизм).
4. `?test=1` → `TEST PASS` (681 + новые smoke-ассерты), консоль чистая.
5. 60 FPS при 60+ монстрах; прирост полигонов не роняет FPS ниже ~50 (как в СПЕКЕ).
6. Геймплей/баланс/логика/экономика/эффекты выстрелов — без изменений (регресс-проверка существующих тестов).
7. Код и спека соответствуют друг другу.

## 13. Принятые решения (зафиксированы)

- Детализация идёт через параметры существующих фабрик (`GEO`-кеш), а не новые сторонние примитивы в горячем цикле.
- Новые детали тень не отбрасывают (только корпуса/основания — прежнее правило).
- Пятна/волны/скосы — детерминированные от seed карты.
- Фон: 0xcfe8ff; `PALETTE` единая для пола/дорожки/семей башен.
- Монстры не перекрашиваются (фирменные цвета), детализация — только геометрия и тёмные окантовки.
